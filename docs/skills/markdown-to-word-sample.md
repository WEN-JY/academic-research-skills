# markdown-to-word 综合核对样张

本文档用于检查 `markdown-to-word` 转换后的版式效果，内容刻意覆盖摘要、标题层级、正文段落、图表、公式、参考文献、附录等常见对象。它不是正式论文模板，而是便于快速核对输出质量的测试样张。

## 核对目标

- 正文是否为小四仿宋、1.5 倍行距、首行缩进 2 字符；
- 二级标题是否表现为 `2.1  标题`，三级标题是否表现为 `2.1.1 标题`；
- 图题是否位于图下方，表题是否位于表上方，中英文双标题是否能两行居中展示；
- 公式是否居中，编号是否按章连续；
- 表格是否为三线表，单元格内容是否默认左对齐；
- 参考文献引文是否以上标形式显示。

# 中文摘要

本文以工程管理论文排版场景为背景，构造一个可重复使用的 Markdown 测试样张，用于检查 Word 转换结果在字体、字号、缩进、标题、图表和公式等方面的表现是否稳定。样张包含中英文混排、数字、单位、参考文献上标、块公式、图片说明和附录内容，便于在一次转换后集中核验主要版式对象。

This sample document is designed to verify the post-conversion layout quality of a Markdown-to-Word workflow. # 第1章 绪论

## 1.1  研究背景

工程师学院论文通常要求正文采用仿宋、小四、1.5 倍行距、两端对齐，并保持统一的标题、图表和公式编号规则。对于以 Markdown 起草的章节稿，若能够先转换为可编辑的 Word 文档，再进入模板精修阶段，可以显著降低重复排版成本^[1]。

在学术写作场景中，经常会出现中英文混排、变量表达和单位书写，例如风险暴露记为 $E_t$，贴现率记为 $i$，项目周期为 $12\ \text{month}$。若正文字体、中西文混排和标点规范不一致，最终文稿通常需要额外返工^[2,3]。

### 1.1.1 研究问题

本文样张的核心问题是：给定一份包含常见学位论文对象的 Markdown 文档，转换后的 Word 是否能够为终稿排版提供一个稳定、可检查、可微调的底稿。

### 1.1.2 核对范围

本样张重点覆盖以下对象：

1. 正文段落、标题层级与列表格式；
2. 图题、表题与块公式编号；
3. 中英文混排、参考文献上标和附录结构。

## 1.2  公式与正文衔接示例

风险调整后的项目净现值可表示为：

$$
NPV = \sum_{t=1}^{T} \frac{CF_t}{(1+r_t)^t} - C_0
$$

其中，$CF_t$ 表示第 $t$ 期现金流，$r_t$ 表示对应期的贴现率，$C_0$ 表示初始投资额。若需进一步表达风险补偿项，可定义综合资本成本为：

$$
r_t = r_f + \beta_t \left(R_m - r_f\right) + \lambda_t
$$

### 1.2.1 引用、缩略词与术语示例

企业资源计划可写作 `ERP（Enterprise Resource Planning）`，首次出现时通常需要给出全称。对于项目评价，常同时关注 `ROI`、`IRR` 与 `NPV` 等指标，并要求术语在全文中前后一致^[4]。

# 第2章 研究设计

## 2.1  指标体系示例

第二章用于观察章节切换后，图号、表号和公式号是否重新从本章开始编号。若转换逻辑正确，本章第一条块公式应显示为本章的第一个公式编号。

$$
Score = \sum_{j=1}^{n} w_j x_j
$$

### 2.1.1 变量说明

式中，$w_j$ 表示第 $j$ 个指标的权重，$x_j$ 表示对应的标准化得分，且满足 $\sum_{j=1}^{n} w_j = 1$。当样本量为 $30$ 组、置信水平为 $95\%$ 时，可进一步考察评价模型的稳健性。

## 2.2  列表示例

- 第一项用于观察无序列表的缩进与字体；
- 第二项用于观察中英文混排，例如 Python、Word、Markdown 和 `.docx`；
- 第三项用于观察列表后的正文是否能恢复首行缩进。

列表之后的本段应恢复为普通正文段落样式，而不应继续保持列表缩进。这一段也可用于检查中英文之间的空格处理，以及诸如 risk register、cost baseline 等英文术语在正文中的呈现效果。

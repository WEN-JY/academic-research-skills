# Word 学位论文格式检测与转换 Skill 规则评审稿

## 1. 目标定位

拟新增一个基于 `markdown-to-word` 规则体系扩展的 Word 文档处理 skill，用于将已有 `.docx` 学位论文转换为符合浙江大学工程师学院工程管理硕士论文规范的格式文档。

该 skill 不以模型判断作为主要执行方式，而以 Node.js 脚本直接读取、检测和改写 `.docx` 内部 OOXML 为主，实现可复现、可追踪、可批量执行的格式检测与自动修复。

建议 skill 名称：

- `docx-thesis-format`
- 或 `word-thesis-format`

## 2. 输入与输出

### 2.1 输入文件

- 已有 Word 文档：`.docx`
- 可选规则配置：`rules/engineering-college.json`
- 可选模板文档：`assets/engineering-college-template.docx`

### 2.2 检测输出

检测脚本输出：

- `report.md`：面向用户阅读的检测报告
- `report.json`：机器可读的检测结果

报告应包含不合规项类型、所在位置、当前格式、目标格式、是否可自动修复和修复建议。

### 2.3 转换输出

转换脚本输出：

- `原文件名.formatted.docx`
- `原文件名.fix-report.md`
- `原文件名.fix-report.json`

转换过程不得覆盖原文件。

## 3. 技术实现原则

### 3.1 基本策略

`.docx` 本质为 ZIP 包，内部核心内容为 OOXML。脚本应执行如下流程：

1. 解压 `.docx`
2. 读取 `word/document.xml`
3. 读取 `word/styles.xml`
4. 读取 `word/numbering.xml`
5. 读取 `word/header*.xml` 与 `word/footer*.xml`
6. 解析段落、表格、图片、公式、节属性
7. 输出检测报告
8. 按规则改写 XML
9. 重新打包为新的 `.docx`

### 3.2 不建议方案

不建议使用 `docx` 库重新生成整篇文档，因为已有 Word 文档可能包含批注、修订痕迹、域代码、自动目录、交叉引用、图片浮动布局、复杂表格、页眉页脚分节等结构。全文重建容易丢失这些结构，最佳方案是原地修改 OOXML。

### 3.3 推荐 Node.js 模块

- `jszip`：读取和重新打包 `.docx`
- `fast-xml-parser` 或 `xml-js`：解析和序列化 OOXML
- `commander`：命令行参数
- `chalk`：终端报告美化

当前 `markdown-to-word` skill 已包含 `docx`、`jszip`、`xml-js` 等依赖，可优先复用或迁移。

## 4. 命令设计

### 4.1 检测命令

```bash
skills/docx-thesis-format/check_docx_format.sh input.docx
```

可选参数：

```bash
skills/docx-thesis-format/check_docx_format.sh \
  --rules rules/engineering-college.json \
  --out report.md \
  input.docx
```

### 4.2 修复命令

```bash
skills/docx-thesis-format/fix_docx_format.sh input.docx
```

可选参数：

```bash
skills/docx-thesis-format/fix_docx_format.sh \
  --rules rules/engineering-college.json \
  --out output.docx \
  --report fix-report.md \
  input.docx
```

### 4.3 检测加修复命令

```bash
skills/docx-thesis-format/format_docx.sh input.docx
```

执行顺序为初始检测、自动修复、生成修复后文档、再次检测、输出最终报告。

## 5. 通用版式规则

### 5.1 正文字体

正文中文：

- 字体：仿宋
- 字号：小四号，12 pt

正文英文与数字：

- 字体：Times New Roman
- 字号：小四号，12 pt

检测项：

- 中文字体是否为仿宋
- 英文和数字是否为 Times New Roman
- 字号是否为小四号

自动修复：

- 可修复普通正文段落 run 字体与字号
- 对公式、代码、图中文字、嵌入对象不强制修改

### 5.2 正文段落

正文段落：

- 首行缩进：2 字符
- 段前：0 磅
- 段后：0 磅
- 行距：1.5 倍
- 对齐方式：两端对齐

检测项：

- 是否缺少首行缩进
- 是否段前不为 0 磅
- 是否段后不为 0 磅
- 是否行距不符合 1.5 倍
- 是否未两端对齐

自动修复：

- 普通正文段落可自动修复
- 标题、图题、表题、公式、参考文献、目录、页眉页脚不套用正文缩进规则

## 6. 标题规则

### 6.1 章标题

章标题格式：

- 示例：`第1章 绪论`
- 字体：仿宋
- 字号：小三号
- 加粗
- 居中
- 段前段后按论文正文标题规则统一

识别规则：

- 匹配 `^第[一二三四五六七八九十0-9]+章`
- 或匹配 `^第\d+章`

自动修复：

- 设置章标题样式
- 记录当前章号，供公式、图、表编号使用

### 6.2 节标题

节标题格式：

- 示例：`2.1  节的标题`
- 编号与标题文本之间保留两个空格
- 两个空格的字体为宋体
- 标题主体字体按标题样式统一

识别规则：

- 匹配 `^\d+\.\d+\s+`

检测项：

- 编号是否为 `章号.节号`
- 编号与文本之间是否为两个空格
- 空格 run 是否为宋体
- 是否错误写成一个空格或多个空格

自动修复：

- 将编号与文本之间统一改为两个空格
- 将空格 run 字体设为宋体
- 不改变标题文本内容

### 6.3 小节标题

小节标题格式：

- 示例：`2.1.1 小节标题`
- 编号与标题文本之间保留一个空格
- 空格的字体为宋体
- 标题主体字体按标题样式统一

识别规则：

- 匹配 `^\d+\.\d+\.\d+\s+`

检测项：

- 编号是否为 `章号.节号.小节号`
- 编号与文本之间是否为一个空格
- 空格 run 是否为宋体

自动修复：

- 将编号与文本之间统一改为一个空格
- 将空格 run 字体设为宋体
- 不改变标题文本内容

## 7. 公式规则

### 7.1 公式编号格式

需要引用的公式或重要公式应编号，编号按章编排。

正文公式编号：

- 第 1 章第 1 个公式：`（1-1）`
- 第 1 章第 2 个公式：`（1-2）`
- 第 2 章第 1 个公式：`（2-1）`

附录公式编号：

- 附录 A 第 1 个公式：`（A-1）`
- 附录 A 第 2 个公式：`（A-2）`

### 7.2 公式排版

公式排版目标：

- 公式主体居中
- 公式编号右对齐
- 编号使用中文全角括号：`（` 与 `）`
- 编号与章节同步自增

推荐 OOXML 实现：

- 优先使用三列表格实现：左列空白、公式居中、编号右对齐
- 表格边框设为无边框
- 表格宽度为页面正文宽度

备选实现：

- 使用制表位：居中制表位放公式，右对齐制表位放编号

### 7.3 公式检测

检测项：

- 是否存在可识别的公式段落
- 公式是否居中
- 编号是否右对齐
- 编号是否符合 `（章号-序号）`
- 章内序号是否连续
- 是否误用英文括号 `(1-1)`
- 是否误用图表式编号 `1.1`

### 7.4 公式自动修复

自动修复：

- 按章重新编号
- 将英文括号改为中文全角括号
- 将公式段落改为居中公式加右对齐编号结构
- 修复公式编号中的空格、半角横线等问题

谨慎处理：

- 复杂多行公式
- 公式组
- 带推导编号的连续公式
- 由图片表示的公式

这些情况应优先检测并报告，必要时保留原结构。

## 8. 图编号与图题规则

### 8.1 图编号格式

图编号按章内自增，格式为：

- `图1.1`
- `图1.2`
- `图2.1`

其中第一个数字为章号，第二个数字为本章内图序号。

### 8.2 图题位置与格式

图题规则：

- 图题置于图下方
- 图题居中
- 中文图题格式：`图1.1 图题名称`
- 英文图题可置于中文图题下一行：`Figure 1.1 English Caption`

### 8.3 图题检测

检测项：

- 是否存在图题
- 图题是否位于图片下方
- 图编号是否为 `图章号.序号`
- 是否误用 `图1-1`
- 是否缺少编号
- 是否章内编号不连续
- 是否图编号与当前章号不一致

### 8.4 图题自动修复

自动修复：

- 将 `图1-1` 改为 `图1.1`
- 按当前章号和章内图序号重编号
- 将图题段落居中

谨慎处理：

- 多图组合
- 子图 `a）`、`b）`
- 图片与图题中间存在说明段
- 浮动图片导致 XML 顺序与视觉顺序不一致

这些情况应检测并报告，必要时不强制移动段落。

## 9. 表编号与表题规则

### 9.1 表编号格式

表编号按章内自增，格式为：

- `表1.1`
- `表1.2`
- `表2.1`

其中第一个数字为章号，第二个数字为本章内表序号。

### 9.2 表题位置与格式

表题规则：

- 表题置于表上方
- 表题居中
- 中文表题格式：`表1.1 表题名称`
- 英文表题可置于中文表题下一行：`Table 1.1 English Caption`

### 9.3 表格格式

表格原则上采用三线表：

- 顶线
- 表头下线
- 底线
- 不使用竖线
- 单元格内容水平居左对齐

### 9.4 表题与表格检测

检测项：

- 是否存在表题
- 表题是否位于表格上方
- 表编号是否为 `表章号.序号`
- 是否误用 `表1-1`
- 是否缺少编号
- 是否章内编号不连续
- 是否表编号与当前章号不一致
- 表格是否符合三线表要求
- 单元格内容是否水平居左对齐

### 9.5 表题与表格自动修复

自动修复：

- 将 `表1-1` 改为 `表1.1`
- 按当前章号和章内表序号重编号
- 将表题段落居中
- 将普通表格边框改为三线表
- 将表格单元格内容统一设为水平居左对齐

谨慎处理：

- 合并单元格复杂表
- 多级表头
- 横向页面中的宽表
- 附录表

这些情况应检测并报告，必要时只修复编号和表题段落，不强制改表格结构。

## 10. 参考文献规则

### 10.1 编排顺序

参考文献应按正文引用顺序编排，采用连续数字编号。

编号格式：

- `[1]`
- `[2]`
- `[3]`

### 10.2 文献类型标识

常见文献类型：

- 专著：`[M]`
- 论文集：`[C]`
- 报纸文章：`[N]`
- 期刊文章：`[J]`
- 学位论文：`[D]`
- 报告：`[R]`
- 标准：`[S]`
- 专利：`[P]`
- 电子文献：`[EB/OL]`

### 10.3 参考文献格式

期刊：

```text
[序号] 作者．题名[J]．刊名．出版年，卷(期): 起止页码.
```

专著：

```text
[序号] 作者．书名[M]．版次(第一版可略)．出版地：出版社，出版年∶起止页码.
```

学位论文：

```text
[序号] 作者．题名[D]．保存地点：保存单位，年份.
```

标准：

```text
[序号] 标准编号，标准名称[S]．出版地：出版者，出版年.
```

电子文献：

```text
[序号] 作者．题名[电子文献及载体类型标识]．文献出处，日期.
```

### 10.4 参考文献检测

检测项：

- 是否存在 `参考文献` 标题
- 参考文献编号是否连续
- 正文引用编号是否均能在文末找到
- 文末参考文献是否均被正文引用
- 是否使用中括号编号
- 是否缺少文献类型标识
- 中文标点与英文标点是否混用严重
- 是否存在明显多余空格

### 10.5 参考文献自动修复

自动修复：

- 修复编号连续性
- 统一编号为 `[n]`
- 去除编号后多余空格
- 尽量统一常见中文标点

不自动修复：

- 作者真实姓名
- 出版年真实性
- 文献题名真实性
- 文献类型真实性
- 引用顺序涉及正文语义时不强制重排

这些项目应输出为人工复核项。

## 11. 摘要与关键词规则

### 11.1 中文摘要

中文摘要要求：

- 摘要应概括研究目的、内容、方法、创新性成果及意义
- 不宜使用公式
- 不宜使用图表
- 不标注引用文献
- 字数一般为 300–500 字左右

关键词：

- 另起一行
- 格式：`关键词：关键词1；关键词2；关键词3`
- 数量：4–8 个
- 关键词之间建议使用中文分号

### 11.2 英文摘要

英文摘要要求：

- 与中文摘要内容相对应
- 实词数量一般为 300–500 个左右
- 英文摘要和关键词使用 Times New Roman 小四号

关键词：

- 格式：`Keywords: keyword 1, keyword 2, keyword 3`
- 内容应与中文关键词对应

### 11.3 检测与修复

检测项：

- 是否存在中文摘要
- 是否存在英文摘要
- 是否存在关键词
- 中文关键词数量是否为 4–8 个
- 摘要中是否出现公式、图表或引用编号
- 英文摘要是否使用 Times New Roman

自动修复：

- 修复摘要与关键词段落字体、字号
- 修复 `关键词` 与 `Keywords` 段落基础格式

不自动修复：

- 摘要内容是否完整
- 中英文摘要语义是否一致
- 关键词是否准确

这些项目应输出为人工复核项。

## 12. 目录、图目录与表目录规则

### 12.1 目录结构

目录应包含：

- 致谢
- 摘要
- Abstract
- 图目录
- 表目录
- 各章、节、小节
- 参考文献
- 附录
- 作者简历

### 12.2 检测项

检测项：

- 是否存在目录
- 是否存在图目录
- 是否存在表目录
- 目录项层级是否与标题层级一致
- 是否存在明显缺失的章标题
- 是否存在明显错误页码

### 12.3 自动修复策略

自动修复：

- 可修复标题样式，使 Word 能重新生成目录
- 可插入目录域代码

不建议脚本直接计算最终页码。Word 分页依赖字体、打印机、平台和版面渲染，Node 脚本无法完全复刻 Word 排版引擎。

建议处理方式：

- 脚本修复标题样式和目录域
- 用户在 Word 中执行“更新整个目录”

## 13. 页眉页脚规则

### 13.1 页眉页脚处理范围

脚本应检测和修复：

- 是否存在页眉
- 是否存在页脚
- 是否存在页码
- 页码位置是否符合配置
- 不同分节是否页眉页脚断开或继承异常
- 奇偶页设置是否异常
- 首页不同设置是否异常

### 13.2 自动修复策略

自动修复：

- 插入或修复页码域
- 统一页眉页脚字体与字号
- 清理异常空页眉、空页脚
- 按配置设置首页不同、奇偶页不同

待学院进一步确认项：

- 页眉具体文字内容
- 页眉横线要求
- 页码位于页脚居中还是外侧
- 前置部分是否使用罗马数字页码
- 正文是否从第 1 页重新编号

在规则未确认前，脚本应只检测并报告，不强制写入具体页眉文字。

## 14. 前置页面规则

前置页面包括：

- 封面
- 中文题名页
- 独创性声明
- 版权使用授权书
- 致谢
- 中文摘要
- 英文摘要
- 目录
- 图目录
- 表目录

检测项：

- 是否存在必要页面标题
- 顺序是否基本符合规范
- 中文题名页、声明页、授权书是否存在

自动修复：

- 可修复页面标题样式
- 可插入分页符

不自动修复：

- 签名内容
- 日期内容
- 评阅人与答辩委员会信息
- 题名页具体字段真实性

## 15. 附录规则

### 15.1 附录标题

附录标题格式：

- `附录A`
- `附录B`

### 15.2 附录编号

附录中的公式编号：

- `（A-1）`
- `（A-2）`

附录中的图表编号建议按配置处理：

- 可选方案一：`图A.1`、`表A.1`
- 可选方案二：沿正文章号规则

待确认项：

- 学院是否明确要求附录图表编号格式

未确认前，脚本应检测附录图表编号并报告，不强制转换。

## 16. 自动修复优先级

### 16.1 高优先级，可自动修复

- 正文字体、字号、行距、缩进、对齐
- 标题字体、字号、加粗、对齐
- 节标题两个宋体空格
- 小节标题一个宋体空格
- 公式编号格式与章内自增
- 图编号 `图1.1` 格式与章内自增
- 表编号 `表1.1` 格式与章内自增
- 图题居中
- 表题居中
- 三线表基础边框
- 参考文献编号连续性

### 16.2 中优先级，谨慎自动修复

- 页眉页脚
- 页码域
- 目录域
- 图题与图片的位置关系
- 表题与表格的位置关系
- 多行公式
- 复杂表格

### 16.3 低优先级，仅检测提示

- 论文内容逻辑
- 摘要质量
- 中英文摘要语义一致性
- 关键词准确性
- 参考文献真实性
- 图表版权来源
- 物理量符号正斜体是否完全符合学科规范

## 19. 与现有 `markdown-to-word` 的关系

现有 `markdown-to-word` 负责从 Markdown 生成 `.docx`，新 skill 负责对已有 `.docx` 做检测与格式修复。

可复用内容：

- 正文字体、字号、行距、缩进规则
- 标题样式规则
- 三线表规则
- 公式对象处理经验
- Node.js 脚本组织方式

不可直接复用内容：

- `markdown-it` 解析流程
- 从 Markdown token 构建新 Word 文档的生成逻辑

新 skill 的核心应从“生成文档”转为“读取并修复已有文档”。
